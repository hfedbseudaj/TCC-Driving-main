# TTC 校准多车合作：实现与实验核验报告

**日期：2026-11-21**  
**依据：**《TTC校准多车合作_公式与实验方案汇报_2026-11-18》

## 结论范围

本轮把报告中的 E0–E5 实验原型补齐并运行。当前阶段沿用原论文的四类确定性运动学环境：交叉、同向追车、并线、对向接近；没有加入红绿灯、HDV 行为预测、公开数据集或 CARLA。这里的“完成”表示实验脚本、记录和构造场景已运行，不表示完整复现原论文的全部实验或获得实车安全证明。

本轮保留的核心链条是

\[
\delta_i=1-\exp(-\alpha_i\,\mathrm{TTC}),\qquad
s_A^*=\frac{1-\delta_B}{1-\delta_A\delta_B},\qquad
s_B^*=\frac{\delta_B(1-\delta_A)}{1-\delta_A\delta_B}.
\]

`s*` 是双车可分盈余份额，不是车辆动作。新解码器在安全、可达的候选轨迹对中，把份额作为参考，构造场景专用的 `K_e`；多车层为每辆车选一个可执行动作，并在共同安全可行域内处理多个边契约。全局选择在有限候选族中按“未兑现边数、边契约偏差、负福利、固定决胜键”字典序求解。顺序两两基线则按决策前 TTC 排序，依次提交边提案、覆盖共享车辆目标，最后投影到同一联合安全候选族；它是透明重建基线，不是原作者未公开的多车代码。

## 运行环境与实验参数

- 服务器项目：`/data/hhr/TCC-Driving-main`；仅在用户指定的 `/data/hhr` 范围内读写，没有修改服务器环境，也没有停止其他进程。
- GPU 环境：Python 3.7.12、PyTorch 1.13.1+cu117、CUDA 11.7、NVIDIA RTX 3090。E0 与 E4 在 GPU 上执行；纯 Python 运动学的 E1、E2/E3a、E3b、E5 在服务器 CPU 上执行。
- E0：best 检查点训练 seed 608；对照随机初始化 seed 608；两者使用相同场景 trial seeds 100–118，每个原始双车场景 19 次；确定性 pair BEV；位置、速度、航向扰动标准差分别为 0.3 m、0.2 m/s、0.02 rad；最多 80 步。检查点以 strict load 加载。
- E1：四场景各用 trial seeds 101–119，共 19 次；位置和速度扰动标准差 0.3 m、0.2 m/s。交叉解码参数 `α=0.2 s⁻¹`、`η=1.0 s`、净空 0.2 s、候选步长 0.2 s；其他场景使用 `α=0.2 s⁻¹`、`η=4 m`、福利容差 5 m，预测 6 s、步长 0.1 s。
- E3b：交叉三车配对闭环，trial seeds 101–119，承诺权重 0；控制步长 0.2 s、预测时域 2 s、episode 时限 16 s。
- E4：best 检查点 seed 608，trial seeds 101–119，共 19 个配对四格试验；确定性 pair BEV。比较 strict adapter 和允许安全投影两种模式。
- E5：trial seeds 301–330；每个有效“场景 × 车辆数 × 方法”30 次，共 10 组、600 个闭环 episode。位置、速度和加速度扰动标准差分别为 0.3 m、0.2 m/s、0.1 m/s²；控制步长 0.2 s、预测时域 2 s、episode 时限 16 s。车辆包络 4.5 m × 1.8 m，纵向余量 0.5 m、横向余量 0.2 m、预测额外余量 0.5 m；近碰撞阈值为包络净距小于 0.5 m。

| 交叉 | 0/19 / 0 | 0/19 / 0 |

| 并线 | 0/19 / 0 | 0/19 / 4 |
| 对向接近 | 14/19 / 5 | 0/19 / 0 |

best 检查点在追车和对向接近上明显失败；这组单检查点、有限合成扰动结果不能证明训练普遍变差，但足以说明“检查点已加载”不能作为安全有效的证据。随机初始化在这些种子上也不能被当作强基线。原作者没有提供可运行的三/四车脚本，因此 E0 只核验原模块的四类双车场景，不能归因原论文多车碰撞原因。

### E2/E3a：单时刻三车、两条冲突边快照

手工构造的 45 个候选组合中，11 个满足联合安全条件，0 个能同时兑现两条边契约，2 个满足福利下界。全局法和顺序法都选择 `(A,B,C)=(3.0,7.0,4.0) s`，都违约 1 条边、福利为 `−4.0 s`、边契约偏差为 `1.2`；顺序法记录到 `B` 的目标由第一条边的 5.8 s 被第二条边覆盖到 7.0 s。两方法最终方案相同，因此该例证明了覆盖/冲突诊断路径可记录，**没有显示全局法优于顺序法**。第二条 `B—C` 契约是手工构造，不是由原模型生成。此快照不执行车辆，不报告碰撞率。

## 解释边界与后续工作：以新多车合作方法为主

1. **确认 TTC 公式真正驱动合作结果**：在相同安全过滤、候选集和场景 seed 下，比较 TTC 折扣、常数折扣、固定 50/50 份额以及仅按 TTC 排序；扫描 `α`、盈余容差和福利容差，记录 `s*` 改变了多少边契约、最终动作、福利与安全指标。目前 E5 对所有静态冲突边都生成契约，`TTC=∞` 也被截到 `δ=0.99`；需规定无迫近冲突时是否启动 TTC 议价，并核对旧视线闭合 TTC 与各场景实际冲突时刻的对应关系。检查交换车辆 ID 或议价先手后结果是否出现无物理依据的偏置。
2. **定义全车合作的接受条件与数学性质**：目前成对契约使用各自的安全分歧动作，但全局选点没有统一的多车安全分歧方案，也未逐车检验联合计划是否比该分歧方案更好。需定义全车个体收益、个体理性或可解释的补偿/取舍条件，并说明何时边契约可同时兑现、不可兑现时当前有限候选字典序修复保证了什么。精确枚举的最小值不自动给出连续动作或大车组的均衡、最优性及复杂度保证。
3. **统一双车解码与多车闭环接口**：E1 静态解码、E3b 交叉闭环和 E5 通用滚动闭环目前使用不同候选族与时域；`scene_extensions.py` 的静态扩展仍用 `1/TTC` 加权参考，E5 则用 TTC 顺序提交，比较口径不同。需要让同一场景的 `N=2/3/4` 在同一实现和指标下比较。E5 交叉当前只有四车组；并线 `D₂` 的平均份额误差为 0.497，需改进映射并核验实际动作。
4. **拿出多车合作相对强基线的证据**：当前全局法与 TTC 顺序重建在多数构造组上输出相近。需增加自动生成的多边冲突场景，并与保守规则、TTC 排序加投影、只最大化总福利的集中式方案在同初态、同扰动、同安全约束下比较。除碰撞/延迟外，汇总每车动作一致性、未兑现契约、边契约偏差、个体收益与最差车辆延迟；人工 `B—C` 契约只用于教学，不作主要证据。
5. **处理长尾求解和近碰撞**：增加可重复压力种子，保存超时步的候选规模与状态，设计有时限的安全回退或有界搜索；针对四车交叉的 3/30 近碰撞检验安全余量、扰动强度与采样分辨率。需要场景 trial 的区间估计，不能由当前 0 次模型碰撞推出安全保证。
6. **限定旧模型核验的角色**：E0 的原始学习模型失败和 E4 的旧报价适配失败应保留为兼容性/历史基线证据。若论文主张只针对新公式与多车合作，原论文 SL、PPO、REINFORCE、LLM 的完整重训不是当前必需任务；只有把旧学习模型作为正式基线时，才需要修正适配器并增加训练 seed。CARLA 与真实数据属于下一阶段的外部有效性验证，不改变当前四类运动学场景的主线。

2026-11-20 旧 E5 运行的扫掠碰撞检测曾将更新后的状态同时用作区间两端，无法正确检查步间扫掠距离。旧运行记录保留作历史，不用于碰撞结论；本报告的 11-21 E5 使用修正后的 pre-step/post-step 检查。
